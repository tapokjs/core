# История изменений

## 1.0.0 — 2026-11-10

Первый стабильный контракт v1. Инструкция перехода с 0.1.0 приведена ниже.

### Исправления и совместимость с будущими ответами

- `parseBaseExchangeResponse()` игнорирует неизвестные поля ответа и не копирует их в результат; `expires_in` — положительное целое не больше 600 (раньше только ровно 600). Набор scope остаётся строгим. Платформа может расширять ответ и сокращать срок без отказа клиентов.
- `token_type` в ответах token endpoint сравнивается без учёта регистра (RFC 6749) и возвращается нормализованным `"Bearer"`.
- Redirect URI с собственным query: `parseAndValidateAuthorizationCallback()` принимает необязательный `redirectUri`; зарегистрированные параметры должны вернуться без изменений и в том же порядке. Без `redirectUri` поведение прежнее: любой параметр вне протокола отклоняется. Redirect URI с параметром `code`, `state`, `iss`, `error` или `error_description` отклоняется во всех builders и bodies.
- Проверка опций во время выполнения: `uiLocales` и `loginHint` — непустые строки ограниченной длины без управляющих символов; `scopes` — массив; `mode` в `resolveTapokEndpoints()` — `connect` или `base`; `allowedEndpointOrigins` — точные origins (значение со слешем раньше молча не совпадало); issuer проверяется одинаково во всех функциях.
- `address` и `custom_fields` в результате `parseConnectUserInfo()` — обычные изменяемые объекты (раньше свойства были только для чтения).
- Текст ошибки `createConnectRevokeBody()` называет оба допустимых значения `token_type_hint`.

### Новое

- `TapokError` — базовый класс ошибок со стабильным `code`. `TapokCallbackValidationError` наследует его. У класса намеренно нет `cause`: ошибки Tapok содержат только фиксированный текст и коды, их безопасно логировать целиком.
- Тексты ошибок парсеров называют поле, но никогда не цитируют значение из ответа; это закреплено тестом.
- Меньше кода в бандле приложения: таблицы scopes, кодов ошибок и claims больше не попадают в бандл, если не используются. Импорт одной `createAuthorizationSecrets` — 495 B вместо 1 840 B после минификации.
- `tapokEndpoints` заморожен: адреса нельзя подменить во время выполнения.

### Несовместимые изменения

- **`applyOidcAuthorizationOptions` больше не экспортируется.** Это внутренний helper, попавший наружу через `export *`. Параметры `prompt`, `maxAge`, `uiLocales`, `loginHint` передавайте в `buildConnectAuthorizeUrl()` и `buildOidcBaseAuthorizeUrl()`.
- Публичная поверхность — явный список в `src/index.ts`; тест фиксирует имена runtime-экспортов.
- Типы: `BaseExchangeResponse.expires_in` — `number` (было `600`); в `BaseMetadata` и `TapokOidcDiscovery` списки значений — массивы вместо кортежей из одного элемента, `identity_token_signing_alg_values_supported` допускает `RS256`.
- `validateOidcDiscovery()` отклоняет `expectedIssuer` с завершающим слешем и неточные origins в списке доверия.
- Issuer с завершающим слешем в authorize builders сообщает `issuer must have no query or trailing slash` (было `Invalid issuer`).

### Переход с 0.1.0

1. Если вы вызывали `applyOidcAuthorizationOptions()`, передайте те же опции в builder authorize URL.
2. Если ваш код сравнивал `expires_in` Base с литералом `600` на уровне типов, используйте число.
3. Если redirect URI содержит query, передавайте `redirectUri` в `parseAndValidateAuthorizationCallback()`.
4. Ловите `TapokError`, чтобы обработать ошибки Core и SDK одним условием; `TapokCallbackValidationError` и его коды не изменились.

### Ранее в этом разделе

- Документация scope `email` согласована с платформой: адрес провайдера, пользовательский адрес с OTP и стабильный сервисный адрес Tapok. Для сервисного адреса `email_verified: true` означает привязку к аккаунту, а не наличие почтового ящика; такой адрес не подходит для писем и восстановления доступа.

## 0.1.1, не публиковалась

- Парсеры читают собственные поля объекта. Refresh response с `id_token: null` отклоняется, а отсутствие `id_token` остаётся допустимым.
- Issuer с query или fragment отклоняется, включая URL с пустым `?` или `#`.
- Проверка исходников использует только стандартные Web API без глобальных типов Bun и Node.js.
- `prepack` пересобирает ESM и декларации перед созданием архива.
- Архив включает MIT-лицензию и эту историю изменений. Проверка релиза устанавливает архив во внешний проект и проверяет Bun, Node.js, Deno и browser bundle.

Если интеграция передавала некорректные данные напрямую в парсеры, исправьте их до обновления. Версия 0.1.1 в npm не публиковалась; её изменения входят в следующий выпуск.
